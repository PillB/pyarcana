## Highest-risk defects

### 1. Self-attestation is not evidence

The P0 in You Do is the canonical S44 anti-pattern. `portfolio_ready` accepts four learner-editable booleans and `gate_case` returns hard-coded labels. A learner can produce `READY` without a workflow, artifact, SBOM, provenance, protected environment, canary log or rollback.

**Permanent audit invariant:** a boolean/string may summarize a verified control, but it cannot be the sole proof that the control ran.

The same anti-pattern recurs in:
- `dependency_review=True`;
- `attestation_valid=True`;
- `migration_compatible=True`;
- `rollback_tested=True`;
- `logs_redacted=True`;
- `evidence_retained=True`;
- truthy `approved_by`.

### 2. Real target environment must appear before You Do

V3 says controlled CI/cloud. All 8 I Do demos and 24 We Do exercises are essentially local Python predicates/parsers. Local models are acceptable as first scaffolds, but they must connect immediately to actual CI evidence: YAML, run logs, artifacts, attestations, environment protection and rollback output.

**Fixer invariant:** do not delete all simple Python models; convert them into short preflight mental models, then show/require the authentic procedure.

### 3. Digest strings are not artifact identity until measured

Published examples accept `sha256:def`, `sha256:abc`, `sha256:x` because they only test the prefix. Some code also receives the digest as a parameter instead of hashing an artifact.

**Fixer invariant:** use `^sha256:[0-9a-f]{64}$` as syntax validation, but still compute/verify the digest against the actual artifact. String shape alone is not provenance.

### 4. SBOM document hash ≠ artifact digest

The current T2-B model incorrectly requires artifact digest, SBOM digest and provenance subject to be equal. A valid SBOM file has its own content digest. What must bind is the **subject** described/attested by the SBOM/provenance to the artifact identity.

Keep separate fields/concepts:
- `artifact_digest`;
- `sbom_document_digest`;
- `sbom_subject_digest`;
- `provenance_subject_digest`.

The two subject digests should identify the intended artifact. The SBOM document's own hash need not equal the artifact hash.

### 5. Action SHA pinning needs all-actions + repository identity

The current validator overwrites `pin_ok` for each `uses:` line; a final pinned action can hide an earlier `evil/action@v1`. It also accepts any 40-hex reference without proving it belongs to the intended action repository.

**Fixer invariant:** inspect every non-local action reference; require each to satisfy pin policy; retain/verify repository + commit identity. Full-length SHA is the immutable reference form, not complete provenance by itself.

### 6. Attestation generation/verification has explicit permissions and identity

GitHub artifact attestation generation needs a narrowly scoped job with:
- `contents: read`;
- `id-token: write`;
- `attestations: write`.

Verification must check subject and trusted identity/policy (issuer/builder, repository/workflow/revision as appropriate). `attestation_valid=True` is not a replacement.

### 7. Approval must be enforced, not named

Truthy `approved_by` is not independent approval. A protected environment can enforce required reviewers, optionally prevent self-review, restrict branches/tags, and disallow bypass depending on policy/plan.

**Fixer invariant:** represent initiator, reviewer authorization and an actual approval record/policy state; require reviewer != initiator when the lab says independent approval.

### 8. Canary/rollback evidence needs valid domains and last-known-good

Current canary code accepts negative rates/times and does not prove the rollback restored a known-good artifact.

Minimum lab evidence:
- numeric domains validated;
- explicit observation window/sample;
- at least error rate plus one other health/SLO signal for the advanced example;
- `before_digest`, `failed_digest`, `restored_digest`;
- `restored_digest == last_known_good`;
- migration/data compatibility evidence when relevant;
- measured rollback duration against the lab RTO.

### 9. Healthy and incident paths are different states

T4-B currently requires `critical_failure=True` for PASS, so a healthy run becomes `STOP_SILENT_FAILURE`.

**Fixer invariant:** normal-success state and critical-failure-response state must be separate branches. Missing evidence should produce a remediation code matching the missing control (`RETAIN_INCIDENT_EVIDENCE`, not `ASSIGN_INCIDENT_OWNER` when the owner is already present).

### 10. Shared UI can leak obsolete curriculum even when the section source is correct

`SectionView.tsx` uses `demos[sectionId]`. Stable id `multimodal` still maps to learner-facing **“Practica CLIP y Whisper (simulado)”**. This is the real meta/order leak. The developer comment in the TS source is not learner-facing and is not itself a finding.

**Fixer invariant:** preserve stable identity, introduce a semantic/current demo key or explicit S44 override.

### 11. Referenced figures must exist in the registry

S44 declares `S44-permission-scope`, but it is absent from both `FIGURES` and `FIGURE_DATA`. `FigureFrame` returns `null` for unknown ids, so the learner sees no visual.

`S44-supply-chain` does exist in `flows.ts`.

**Fixer invariant:** registry validation should fail CI if a lesson references an unknown figure id. If `S44-permission-scope` is retained, register it and place it with T2-A, where permissions/pinning is taught.

## Pedagogical anti-patterns to watch

### Predicate-repair monoculture
All 24 We Do exercises largely repeat:
1. repair an inverted/simple predicate;
2. classify valid/adversarial/missing dict;
3. write a fail-closed classifier using the same representation.

This teaches the exercise grammar more strongly than CI/CD. E3 does not reliably change representation or context, so transfer is weak.

Preferred variety for S44:
- edit/review YAML;
- inspect a workflow diff;
- locate an unpinned action among several pinned ones;
- compute/re-download/hash an artifact;
- inspect attestation subject/identity;
- diagnose a protected-environment denial;
- read a canary telemetry window;
- prove rollback to last-known-good;
- inspect branch/ruleset evidence;
- repair non-operable release notes.

### Missing topic assessments
V3 requires four authentic topic assessments, each covering both subtopics with an integrated artifact/rubric. S44 has self-check and section exam but not these four required topic evaluations.

### Exam is current but too recall-heavy
The authenticated question bank is correctly retargeted to CI/CD, unlike the Theory playground. However examples such as “Una matrix de CI…” and “Fallar el pipeline si mypy/ruff fallan…” are mostly recognition. Keep retrieval practice, but use artifact/diff/log vignettes for more Level-4 reasoning.

## Language/redaction watchlist for Peruvian Spanish

Current content overuses English/ops terms without enough local explanation: `artifact`, `provenance`, `attestation`, `owner`, `hold`, `breach`, `lead`, `ops`, `environment`, `canary`, `rollback`, `release notes`.

Do not purge necessary industry vocabulary. Introduce it once with causal meaning, then reuse consistently. Example pattern:

> “Una **atestación de artefacto** es un registro firmado que vincula un archivo o imagen con información verificable sobre cómo se construyó. En GitHub Actions, el job que genera esa atestación necesita permisos específicos; después, otro paso puede verificar que el sujeto y la identidad del constructor coinciden con la política esperada.”

Avoid converting every English term into a long parenthetical on every use; explain once, then standardize.

## Runtime counterexamples to keep as regression tests

1. `publish_if(True, "sha256:x", 7)` must **not** publish.
2. Workflow with `evil/action@v1` followed by a pinned action must **not** report all actions pinned.
3. Equal garbage strings `sha256:aaa` for artifact/SBOM/provenance must **not** prove provenance.
4. `canary_ok(-1, 0.01, -999, 120)` must **not** pass.
5. Release-note headings with empty bodies must **not** be operable.
6. A healthy T4-B run must **not** become `STOP_SILENT_FAILURE`.
7. Four manual evidence flags must **not** be able to create `READY`.
8. Every figure id used by S44 must resolve through `FIGURES` or `FIGURE_DATA`.
9. S44 Theory must not contain CLIP/Whisper learner-facing content after stable-id routing.

## Rejected false positives

- **Rename `multimodal`: rejected.** Stable URL/progress key.
- **S44 must close CP-N4-B: rejected.** Canonical gate is S47.
- **Must use a real public cloud: rejected.** Controlled CI/local fixtures are acceptable if they produce real evidence.
- **Caches are incompatible with reproducibility: rejected.** Cache is a speed optimization; defect only appears when it is treated as evidence/source of truth.
- **40-hex action pinning is overkill: rejected.** Current GitHub secure-use guidance explicitly supports full-length commit SHA pinning.
- **Developer comments in the TS file are learner-facing leakage: rejected.** They are source-only; the shared playground is the learner-facing leak.
- **Any secret-scan hit must always rotate credentials: rejected as a universal rule.** Block/classify first; confirmed active exposed credentials require remediation/rotation, while false positives/test secrets have different handling.
