### S17-F20 — A prose approximation is formatted as executable Python inside the core fan-out gate, creating false syntax/semantics.
- **Category:** BITSHIFT_NOTATION_MASQUERADES_AS_COMPARISON
- **Location:** T1-A p2 + T1-A callout
- **Evidence:** The learner-facing contract writes `len(out) >> len(left)` in code formatting to mean 'much greater than'. In Python `>>` is the bitwise right-shift operator, not a comparison. Spot-check: `3 >> 2 == 0` and `10 >> 2 == 2`.
- **Impact:** Debido a este problema, un alumno razonable puede copiar `len(out) >> len(left)` as a fan-out condition and get an integer bit-shift result—often zero—instead of a boolean comparison, or learn that `>>` means 'much greater than' in Python.
- **Proposed fix:** Do not put `>>` in code formatting. Write 'si `len(out)` es mucho mayor que `len(left)`' in prose, or better define an explicit expected row count/cardinality invariant and compare with `!=`, `>`, or a documented threshold.
- **Sources (1):** audit/lessons-only/sections/S17.patch-001.json

### S17-F21 — The prose, executable code and expected output describe different examples and different window sizes.
