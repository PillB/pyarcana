### S49-F37 — The central 'sensitive actions require human approval' contract can false-pass sensitive actions through naming conventions or caller-controlled `approval_required`.
- **Category:** T4-B/HITL/false-green
- **Location:** T4-B theory/I Do/We Do central approval gate
- **Evidence:** Theory/I Do protect only `name.startswith('prod_')`: RED `run_tool('send_email', None, 0)` and `run_tool('delete_case', None, 0)` return `sandbox_ok`. We Do can PASS `sensitive_action='prod_send'` when the record supplies `approval_required=False`.
- **Impact:** The section's defining safety gate can authorize sending/deletion/production-like actions without a human.
- **Attack:** Rename a sensitive tool without the `prod_` prefix or set the self-reported approval requirement false.
- **Defense:** The controlled fixture names its production action `prod_send` and normally sets `approval_required=True`.
- **Proposed fix:** Define tool policy in a trusted registry: each tool/action class declares sensitivity/approval policy server-side; approval is evaluated from tool identity + normalized arguments + resource risk, never caller-supplied `approval_required` or prefixes.
- **Verdict:** CONFIRMED_FINDING P0 because security depends on untrusted naming/flags rather than policy.
