### S42-F03 — El proyecto final puede quedar READY sin Pydantic, tipos ni JSON Schema reales; además acepta valores mal tipados.
- **Category:** STRICT_SCHEMA_NOT_EXECUTED
- **Evidence:** You Do `policy_engine` solo comprueba presencia/extras; contraejemplo: `{case_id:123,status:{bad:1}}` puede llegar a CONTINUE.
- **Impact:** El outcome principal “schema estricto (tipos + rechazo de campos extra)” queda sin evaluar; una API insegura puede aprobar.

- **Proposed fix:** Hacer obligatorio un modelo Pydantic `extra="forbid"`, restricciones de tipo/enum y `model_json_schema()`, con tests válidos/inválidos.

### S42-F11 — La teoría explica correctamente que hostname allowlist sola no basta, pero We Do, You Do y self-check vuelven a host-only y pueden aprobar SSRF por DNS rebinding/resolución interna.

### S42-F13 — `url_allowed` parsea URLs con split, resuelve una sola vez y no ejecuta redirects ni múltiples A/AAAA.
- **Category:** URL_DNS_REDIRECT_MODEL_INCOMPLETE
- **Evidence:** T3-A code: `url.split("://",1)...`; `resolve(host)` una vez.
- **Impact:** Contradice la propia explicación de redirects/DNS y no modela el punto de conexión real.

- **Proposed fix:** Usar `urllib.parse`, validar scheme/host/port, todas las IP resueltas, desactivar redirects o revalidar cada salto y fijar el destino verificado.
