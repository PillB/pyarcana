### S19-F01 — S19 opens by treating S18 outputs as already trustworthy
- **Category:** PREREQUISITE_INTEGRITY
- **Evidence:** Opening: 'El EDA de S18 dejó medianas, tamaños de muestra e incertidumbre.'
- **Impact:** Learner can chart S18 artifacts whose denominators, intervals, provenance and traceability are still unresolved, laundering upstream uncertainty into polished figures.
- **Proposed fix:** Make the handoff conditional: first verify S18 data note, denominator, uncertainty method and exact analytical payload before visualization.
- **Sources (1):** audit/lessons-only/sections/S19.json

### S19-F04 — The claimed visual-inflation factor is never calculated
- **Category:** CODE_CONTRACT_MISMATCH
- **Evidence:** T1-B says calculate '(altura_truco / altura_honesta)'; code prints 0.67 and 0.10 separately. Their ratio, the actual inflation factor under that definition, is 6.67.
- **Impact:** A central integrity gate appears executable but does not produce the metric named by the prose.
- **Proposed fix:** Define the metric precisely and print `factor_inflacion = ratio_truco / ratio_honesto` (=6.67 for the fixture), while explaining what the ratio represents and its limits.
- **Sources (1):** audit/lessons-only/sections/S19.json

- **Impact:** The learner sees a stated executable contract that the worked example does not actually demonstrate.

### S19-F07 — Export contract says savefig is required while the code only simulates metadata
- **Category:** REPRODUCIBILITY
- **Evidence:** T2-B: 'Exporta de verdad con fig.savefig'; code comment says '# simular export metadata' and never calls savefig.
- **Impact:** The exact skill named in the learning outcome—producing a versioned PNG—is not demonstrated, and a metadata dict can pass while no artifact exists.
- **Proposed fix:** Write to BytesIO or a temporary/versioned file with `fig.savefig(..., dpi=120, bbox_inches='tight')`; validate non-zero bytes/format and derive metadata from the created artifact.
- **Sources (1):** audit/lessons-only/sections/S19.json

### S19-F09 — Interactive accessibility contract omits keyboard/focus and tooltip behavior
- **Category:** ACCESSIBILITY
- **Evidence:** T3-A minimal spec is `{filtro, tooltip_template, unidad, campos_visibles}` and discusses hover/tooltips but not keyboard focus, focus order, dismissibility, hoverability or persistence.
- **Impact:** A dashboard can satisfy the lesson's spec while remaining unusable to keyboard and screen-reader users; this conflicts with the section's central accessibility claim.
- **Proposed fix:** Extend the spec with keyboard-reachable controls, focus-visible behavior, accessible names/state, tooltip trigger by focus as well as pointer, and WCAG 1.4.13 behavior when custom hover/focus content is used.
- **Sources (1):** audit/lessons-only/sections/S19.json

## P2 (11)

### S19-F02 — Audience guidance is framed as role stereotype rather than task and decision need
- **Category:** PEDAGOGY_AUDIENCE_MODEL
- **Evidence:** Opening: 'Una gerencia necesita una idea y pocas categorías; un equipo de análisis aguanta más detalle.'
- **Impact:** Teaches learners to simplify by job title instead of matching density to decision, time, expertise and consequence.
- **Proposed fix:** Define audience by decision, time budget, prior knowledge and required drill-down; role can be an example, not the rule.
- **Sources (1):** audit/lessons-only/sections/S19.json

### S19-F03 — Encoding hierarchy is materially oversimplified
- **Category:** VISUAL_PERCEPTION
- **Evidence:** T1-B: 'Jerarquía de encodings: posición > longitud > color > forma.'
- **Impact:** Conflates quantitative accuracy with categorical channels and omits angle/area distinctions; learner may treat hue or shape as ordered quantitative encodings.
- **Proposed fix:** Teach position on common scale and length as strong quantitative channels; distinguish angle/area and explain that hue/shape are primarily categorical, not a universal numeric ranking.
- **Sources (1):** audit/lessons-only/sections/S19.json

### S19-F06 — The multi-panel example silently applies the bar zero-baseline rule to a line chart
- **Category:** AXIS_SEMANTICS
- **Evidence:** T2-B loops over both axes and runs `ax.set_ylim(bottom=0)`, including the panel titled 'Tendencia'.
- **Impact:** Learner may generalize 'all Y axes start at zero', although the section correctly scopes the strict zero rule to bar-length magnitude encodings.
- **Proposed fix:** Apply zero baseline to the bar panel only; teach line-axis choice from analytical purpose and provide sufficient contextual scale.
- **Sources (1):** audit/lessons-only/sections/S19.json
