### S08-F04 — S08 repeatedly relies on exception mechanics to implement quarantine/fail-closed behavior before teaching the mechanism.

### S08-F06 — replace/ignore can silently alter or discard undecodable characters and still yield a str that appears ingestible.

### S08-F08 — A valid logical CSV record spanning multiple physical lines is split before the CSV parser can interpret quoting.
- **Category:** TECHNICAL_CONTRADICTION_CSV_RECORDS
- **Location:** T2-B quarantine_irregular
- **Evidence:** The function calls text.splitlines(keepends=True) and feeds csv.reader one physical line at a time. Standard CSV permits newline characters inside quoted fields.
- **Impact:** A valid record such as C001,"línea uno línea dos" is split into a partial clean row plus a quarantined fragment, corrupting both data and reconciliation.
- **Proposed fix:** Feed the complete text/file object to csv.reader/DictReader with newline='' semantics; track logical record numbers and preserve source evidence separately rather than defining record=physical line.
- **Sources (1):** audit/lessons-only/sections/S08.json

### S08-F18 — The provenance artifact can become internally inconsistent under the exact file-change race the lesson warns about.
- **Category:** PROVENANCE_RACE
- **Location:** T4-A hash_backup.py
- **Evidence:** The pattern copies src to backup and then computes sha256 from src. If src changes/replaces between those two operations, backup bytes and recorded digest can describe different content.
- **Impact:** A reviewer may use a digest recorded in the manifest to identify the backup, even though that digest was computed from a later version of the source path.
- **Proposed fix:** Hash the immutable backup bytes (and optionally compare source hash before/after copy) and record the digest of the exact bytes preserved as evidence.
- **Sources (1):** audit/lessons-only/sections/S08.json

### S08-F19 — The printed label claims process-level behavior that the process does not exhibit.
- **Category:** TECHNICAL_CONTRADICTION_EXIT_STATUS
- **Location:** T4-B manifest.py
- **Evidence:** The prose/callout require exit != 0 on reconcile failure. The example raises ValueError, immediately catches it, prints 'exit != 0:' and then terminates normally.
- **Impact:** The learner can believe catching and printing an exception makes a job fail operationally even though schedulers/shells see exit status 0.
- **Proposed fix:** Separate library validation from process boundary: let the exception remain uncaught in the failing-run demonstration or catch it in main and call sys.exit(1); never label a caught exception as proof of non-zero exit.
- **Sources (1):** audit/lessons-only/sections/S08.json

### S08-F17 — A digest is useful for content identity/change detection but does not prove who supplied the file, when it was acquired, or that it is authentic; 'changes completely' is an overstatement rather than a
- **Category:** HASH_PROVENANCE_OVERCLAIM
- **Location:** opening + T4-A
- **Evidence:** sha256 is described as a fingerprint that 'changes completely' for any one-byte change and is grouped into provenance.
- **Impact:** The learner can treat a matching hash as proof of source authenticity/provenance rather than proof that two byte sequences match for practical purposes.
- **Proposed fix:** Define SHA-256 as a content fingerprint: same bytes -> same digest; a changed file is overwhelmingly likely to produce a different digest. State explicitly that the hash does not prove authorship or acquisition source.
- **Sources (1):** audit/lessons-only/sections/S08.json

### S08-F20 — n_in is never defined precisely enough: physical lines, nonblank logical CSV records, or parser-emitted records are different quantities.

- **Proposed fix:** Define n_in as the number of logical data records attempted after the header under the source CSV parser policy; separately count ignored blank physical lines if the policy permits them.
- **Sources (1):** audit/lessons-only/sections/S08.json
