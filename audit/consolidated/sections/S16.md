## P1 (15)

### S16-F01 — The lesson teaches isolated checks but never shows the causal pipeline raw input → rule results → disjoint clean/quarantine → metrics → pass/fail.
- **Category:** GATE_NOT_COMPOSED_OUTCOME_NOT_TAUGHT
- **Location:** tagline + opening p5 + reference p3 + T4-B
- **Evidence:** The section promises a fail-closed quality suite, but each theory block operates on a fresh hand-built DataFrame. T4-B manually creates clean/quarantine tables instead of deriving them from the null, duplicate, normalization, schema and cross-field rules taught earlier.
- **Impact:** Due to this problem, a reasonable learner can reproduce eight demos yet still be unable to build the integrated quality gate promised by the tagline and roadmap.
- **Proposed fix:** Add one compact theory example `run_quality_gate(raw, contract)` that reuses the taught checks and derives clean, quarantine, metrics and audit events from one input.
- **Sources (1):** audit/lessons-only/sections/S16.json

### S16-F03 — Optionality answers whether null is allowed, not whether replacing it with a value is semantically valid.
- **Category:** NULL_POLICY_TOO_COARSE_OPTIONAL_NOT_IMPUTABLE
- **Location:** opening p2 + T1-A + T1-B
- **Evidence:** The opening distinguishes absent, not-applicable and real zero, but the executable policy reduces fields to required\|optional. T1-B then allows median imputation for an optional field solely when its null rate is below a cap.
- **Impact:** Due to this problem, a reasonable learner can infer `optional + null_rate <= cap => safe to impute` and invent values where null actually means not applicable or deliberately unknown.
- **Proposed fix:** Extend the field policy with an explicit null action/meaning such as required_fail, optional_keep_null or optional_impute(method=...), and state that the cap limits volume but does not authorize imputation.
- **Sources (1):** audit/lessons-only/sections/S16.json

### S16-F04 — A next-section abstraction is used as the core implementation shortcut before it is taught.
- **Category:** FUTURE_KNOWLEDGE_LEAK_GROUPBY_TRANSFORM
- **Location:** T2-A p2 + dups.py
- **Evidence:** The conflict detector uses `groupby(...).transform('nunique')`, but the authoritative roadmap schedules groupby/agg/transform for S17. S16 gives syntax but no mental model of grouping, per-group aggregation or transform shape preservation.
- **Impact:** Due to this problem, a reasonable learner can cargo-cult a groupby/transform expression without being able to predict which group a row belongs to or why the result aligns back to the original rows.
- **Proposed fix:** Use a small dict/set-based conflict detector with already learned constructs in S16, then teach groupby/transform from first principles in S17.
- **Sources (1):** audit/lessons-only/sections/S16.json

### S16-F05 — The executable classifier is narrower/different from the contract it claims to demonstrate. Provenance columns such as batch/source would prevent otherwise business-identical rows from being classifie
- **Category:** DUPLICATE_CLASSIFIER_DOES_NOT_MATCH_CONTRACT

### S16-F06 — Input order is silently promoted into a business-resolution policy.
- **Category:** ARBITRARY_CONFLICT_RESOLUTION_KEEP_FIRST
- **Location:** T2-B p2-p3 + key_evidence.py
- **Evidence:** For two C001 rows with scores 0.9 and 0.4 from sources a/b, the lesson resolves the key with `drop_duplicates(key, keep='first')`. No source-priority, timestamp, authoritative-system or review rule explains why input order should win.
- **Impact:** Due to this problem, a reasonable learner can choose whichever conflicting row happened to arrive first and treat that arbitrary ordering as a defensible master-record resolution.
- **Proposed fix:** For unresolved conflicts, quarantine the whole key and exclude it from clean. Demonstrate promotion only after a deterministic documented rule such as authoritative-source priority or reviewed timestamp.

### S16-F07 — The two outputs called clean and quarantine are not mutually exclusive even though quarantine is later defined as rejected rows.
- **Category:** CLEAN_QUARANTINE_OVERLAP_BREAKS_ACCOUNTING
- **Location:** T2-B key_evidence.py + T4-B metrics contract
- **Evidence:** `quarantine = df.loc[dup_mask]` contains both C001 rows, while `clean = df.drop_duplicates(key, keep='first')` also contains the first C001 row. For the three-row example, clean has 2 rows and quarantine has 2 rows: one source row is counted in both sets.
- **Impact:** Due to this problem, a reasonable learner can report `rows_clean + rows_quarantine > rows_in`, double-count excluded data, and feed a quarantined row into S17.
- **Proposed fix:** Make outputs disjoint by default: unresolved duplicate-key groups go entirely to quarantine; only a row explicitly resolved/promoted leaves quarantine and enters clean, with an audit event.
- **Sources (1):** audit/lessons-only/sections/S16.json

### S16-F08 — The normalizer is incompatible with the section's own null model.
- **Category:** NORMALIZATION_NOT_NULL_SAFE
- **Location:** T3-A normalize.py
- **Evidence:** `stripped = df['region_raw'].str.strip()` can preserve missing values, but the following list comprehension calls `x.upper()` and `x.title()` unconditionally. `None`/`pd.NA` therefore raises instead of preserving or classifying the null.
- **Impact:** Due to this problem, a reasonable learner can apply the canonical normalizer to an optional missing region and crash the batch instead of preserving null or routing it according to policy.
- **Proposed fix:** Use a null-safe `norm_region(x)` that returns `pd.NA` for missing inputs before applying `.upper()`/`.title()` to actual strings.
- **Sources (1):** audit/lessons-only/sections/S16.json

### S16-F09 — Invalid normalization outcomes are either silently converted to missing or crash outside the promised gate evidence model.
- **Category:** NORMALIZATION_FAILURES_ARE_SILENT_OR_UNSTRUCTURED
- **Location:** T3-A p2-p3 + normalize.py
- **Evidence:** `norm_money('abc')` becomes NaN through `or 'nan'` with no reason/count; malformed values such as repeated separators can raise ValueError; `parse_fecha` converts any unrecognized date to `pd.NaT`. The lesson preserves raw columns but emits no normalization-failure mask, code or quarantine evidence.
- **Impact:** Due to this problem, a reasonable learner can transform bad source tokens into NaN/NaT without counting the failure and believe preserving `raw` alone satisfies «nunca arreglar en silencio».
- **Proposed fix:** After parsing, compute `raw.notna() & parsed.isna()` failure masks (or return value+reason) and attach structured reason codes/counts; catch deliberate parse failures at the quality boundary.
- **Sources (1):** audit/lessons-only/sections/S16.json

### S16-F10 — The learner is asked to execute statistical formulas before the concepts that make them interpretable are taught.
- **Category:** FUTURE_KNOWLEDGE_LEAK_STATISTICS
- **Location:** T1-B median + T3-B median/quantile/IQR/z-score
- **Evidence:** S16 uses median imputation and then introduces quantiles, IQR, the 1.5×IQR rule and mentions z-score, while the authoritative roadmap schedules center, dispersion and quantiles for S18. No local explanation establishes what a median/quantile/IQR represents or why 1.5 is a candidate heuristic.
- **Impact:** Due to this problem, a reasonable learner can memorize `1.5 * IQR` as a universal truth detector or use median merely as a magic function without understanding the decision it encodes.
- **Proposed fix:** Give one bounded micro-model: median = middle value after ordering; Q1/Q3 split the lower/upper quarters; IQR=Q3-Q1; 1.5×IQR is a conventional candidate flag, not a business verdict. Defer z-score and deeper statistics to S18.
- **Sources (1):** audit/lessons-only/sections/S16.json

## P2 (7)

### S16-F02 — A storage sentinel is equated with one semantic cause.
- **Category:** NAN_SEMANTIC_OVERGENERALIZATION
- **Location:** opening p2
- **Evidence:** The text states `NaN` means «no sé». In pandas/NumPy-backed columns NaN can be used as a missing-value sentinel, but IEEE NaN means Not a Number and does not encode why a value is absent or invalid.
- **Impact:** Due to this problem, a reasonable learner can treat every NaN as evidence that the source value was simply unknown, even when it arose from coercion or numeric computation.
- **Proposed fix:** Say: «En estas columnas pandas usa NaN como marca de valor faltante; NaN no explica por qué falta. Conserva además el motivo: ausente en origen, coerción fallida, etc.»
- **Sources (1):** audit/lessons-only/sections/S16.json

### S16-F13 — The output shape required to connect a rule failure to T4-B quarantine is missing.

- **Impact:** Due to this problem, a reasonable learner can identify row 1 as bad but still not know how to produce the promised row-level reason evidence when several rules fail.

### S16-F16 — A behavioral governance property is attributed to an unconstrained mutable container.
