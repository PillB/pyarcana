**Blockers**
- [blocker] [O] Three regex We Do starters ship corrupted, and the missing piece is syntax the section never teaches, so Lucía cannot reach the expected output without opening the solution. The `.ts` source writes `\w`, `\d` and `\b` with a single backslash inside a JS template literal. JS then drops the backslash (`\w` becomes `w`, `\d` becomes `d`) or turns `\b` into a backspace control character (U+0008), visible in the JSON for weDo.steps[15]. The solutions use `\\w` and are fine.
  - weDo.steps[13]: the starter pattern is `r'^(w+) (w+)$'`. It never matches «Ana Quispe», so the starter prints `None`. The feedback describes something else: «El starter invertía `group(1)`/`group(2)`». Fixing only the crossed groups, as instructed, still prints `None`.
  - weDo.steps[16]: the instruction says the only defect is case: «(E2: corrige el case del starter sin tutorial.)». After changing `[a-z]` to `[A-Z]`, the pattern `r'[A-Z]{3}-d{2}'` still returns `[]`, because `d` is a literal letter.
  - weDo.steps[15]: the instruction describes the starter as «compila `\b\d{9}\b`», but the editor shows `r'<BS>d{9}<BS>'`, with invisible control characters.

  — where: `weDo.steps[13].starterCode`, `weDo.steps[15].starterCode`, `weDo.steps[16].starterCode` (source lines ~1267, ~1349–1351, ~1393 of the `.ts`) — evidence: «pat = re.compile(r'^(w+) (w+)$')», «codes = re.findall(r'[a-z]{3}-d{2}', log)» — fix: `src/lib/course/sections/s07-text-unicode-regex.ts`: double the backslashes in these starters (`\\w`, `\\d`, `\\b`), and add a check that every starter `code` string is free of U+0008 and of regex escapes stripped of their backslash (the defect is invisible to CPython tests because only solutions are executed).
