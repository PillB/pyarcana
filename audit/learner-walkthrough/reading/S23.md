- Exam tests the badge claim (`responsible_machine_learning_evaluation` [S10+S23], `integrated_data_science_practice`, `integrated_ml_engineering_practice`, plus progress/capstone badges `progress_phase1_walked`, `progress_journey_completed`, `integrated_python_ai_capstone_independent`): no [O] — Three competency badges list S23 as ML or deep-learning evidence. Fix: `src/lib/eligibility/badge_catalog.json`: move S23 from the ML badges to the automation badges.
- Value: mixed — The judgement content is good and current: role-first locators, condition waits instead of sleeps, verifying the downloaded file, retrying only transient errors, API/export first, handing CAPTCHA and ToS cases to a human. But a paying learner finishes a section called «Browser RPA con Playwright» without ever running Playwright or seeing a web page's structure. GitHub-readiness of the You Do: weak. It is a mostly pre-written dict script plus a runbook, with no README, tests, data or demo required, and a reviewer would see no browser automation in it.
- Browser-runtime risks (Pyodide 0.26.2): `theory[1].code` (`playwright_sketch.py`) does `from playwright.sync_api import sync_playwright` at import time, so it raises ModuleNotFoundError if run in the browser. Its printed output («sketch_ready True») is also tautological. All other snippets are stdlib-only (`hashlib`, dicts; `str | None` in the You Do is fine on Pyodide's Python 3.12), so I infer no other risk.
