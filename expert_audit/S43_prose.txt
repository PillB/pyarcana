Bases, usuarios no root y tamaño

Con el cache de layers en orden (T1-A), endureces la imagen de runtime. Una base mínima reduce superficie de ataque, pero debe seguir parchable: fija tag o digest (nunca código suelto). Distroless/slim recortan shell y paquetes; el trade-off es depuración más difícil (lo resuelves en T4-B con shells efímeros, no root permanente). Ejecuta como UID de aplicación (≥1000), sin código ni capabilities extras, y acota el tamaño runtime (MB).

Dependencias, migraciones y datos efímeros

El stack de T3-A necesita orden de arranque de datos. Las migraciones de esquema son jobs controlados: patrón expand/contract (primero agregas columnas compatibles con código viejo; luego retiras lo obsoleto). Un código incompatible con código aún en producción bloquea el release. Datos efímeros (tmp, cache) se recrean; datos durables (DB) exigen backup y drill de restore antes de confiar en el rollback.
