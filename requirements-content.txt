# ── Why these are pinned, not floating ───────────────────────────────────────
# pandas 3.0 changed the default string dtype from `object` to `str`. The course
# teaches dtype contracts explicitly and prints them — S15 alone declares
# `{'cliente_id': 'object', 'monto': 'float64'}` — so an unpinned install
# silently invalidates those outputs. CI proved it: with pandas 3.0.5, six S15
# artifacts failed, five of them dtype strings that no longer match.
#
# This pin makes the gate testable. It does NOT mean the content is current: a
# learner running `pip install pandas` today gets 3.x and will see `str` where
# the course says `object`. Migrating the dtype-printing content to pandas 3 is
# tracked separately — see audit/content-campaign-c04/registers/07_pandas3_gap.md.
