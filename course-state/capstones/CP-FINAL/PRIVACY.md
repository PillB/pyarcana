# PRIVACY — CP-FINAL integration platform

## Data minimisation
- The shared synthetic scenario contains **only** synthetic data (client
  ACME-001, synthetic transactions, synthetic entities). No real PII is
  ingested at any layer.
- The scenario is generated by `data/generate.py` and is CC0-licensed.
- Each subsystem receives only the fields declared in its contract; no
  subsystem has access to fields outside its declared schema.

## Proveniencia (esto es, la trazabilidad: de dónde viene cada dato o resultado)
- Every output row in the integration trace carries a `source` field
  identifying which subsystem produced it.
- The `shared_trace_id` propagates across all 12 calls, so any output can
  be traced back to its origin.
- The `dependency_graph.json` records the upstream → CP-FINAL edge for
  each subsystem.

## Access control
- The `familiarity.review` subsystem enforces a three-way separation:
  entity-resolution evidence, relationship evidence, and risk decisions
  are kept in separate fields. No automatic adverse decision is made.
- The `graph.investigate` subsystem filters edges by authorisation scope
  (`internal` vs `restricted`); a viewer without `restricted` scope
  cannot see restricted edges.
- The `copilot.run` subsystem enforces per-document ACLs before retrieval;
  docs the caller cannot read are never returned.

## Redaction
- The copilot's `tracing.redact()` scrubs emails, bearer tokens,
  secret-looking key/value pairs, and long opaque tokens before any trace
  is persisted.
- The aggregated integration trace inherits this redaction: every span
  from every subsystem passes through the copilot's redaction filter
  before being included in the `IntegrationBundle`.

## Correction and appeal
- The `graph.investigate` subsystem supports analyst notes and a
  correction mechanism for disputing an edge.
- The `triage.score` subsystem supports abstention: uncertain cases
  route to human review with a stated reason.
- The `no_go.py` evaluation includes a `correction_recommended` field
  when a subsystem reports a violation that a human should review.

## No automated adverse decision
- No subsystem in the integration makes an automatic adverse decision.
- The `familiarity.review` subsystem explicitly does **not** infer fraud,
  kinship, collusion, criminal association, beneficial ownership, or
  causal relationship.
- The `triage.score` subsystem routes uncertain cases to human review;
  it does not make unreviewed adverse decisions.

## Data retention
- The integration trace is ephemeral: it exists in memory during the run
  and is written to `run_state.json` only for debugging and reproducibility.
- No real user accounts, no server-side progress, no persistent database
  on the GitHub Pages edition.
- The `backup_restore.py` snapshot is in-memory and discarded after the
  run completes.
