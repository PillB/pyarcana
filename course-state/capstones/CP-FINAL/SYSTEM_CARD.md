# system card — CP-FINAL Enterprise Relationship & Operations Intelligence Platform

**Package version:** 2.0.0 · **Principal gate:** S52 · **Integration of:** 12 upstream capstones

## 1. What the system is

CP-FINAL is the transversal capstone that integrates the twelve upstream level
capstones (CP-N1-A through CP-N4-C) into one defensible platform through
explicit, versioned interfaces. It is *not* a folder of twelve unrelated
repositories: it is a contract-bound integration where each subsystem exposes
a typed contract, every contract is tested, and the whole assembly is
exercised on a single shared synthetic scenario (client ACME-001).

The public entry points are the twelve versioned interfaces declared in
`integration/contracts.py` and the end-to-end trace in `integration/e2e_test.py`.

## 2. Intended use & users

Learners in the L4 band of the PyArcana curriculum demonstrating that they
can integrate, observe, secure and defend a bounded production-style data
and AI system. The platform is exercised on synthetic data only; no claim
is made of fraud prevention, money saved, real-organisation improvement,
production accuracy, or enterprise scale.

## 4. Failure modes & mitigations

| Failure | Mitigation |
|---|---|
| Contract mismatch (one subsystem emits a response the consumer cannot parse) | 12 contract tests assert request/response schema conformance; all interfaces are versioned (`/v1/`) and additive-only |
| Dependency cascade failure (one subsystem outage takes down the platform) | Per-interface timeout + fallback; the copilot's no-key double; end-to-end test asserts a partial failure produces `noGo=true` rather than a crash |
| Shared-state corruption (the shared synthetic scenario is mutated) | The synthetic scenario is immutable (JSON fixture under `data/`); the shared traceId is generated once and propagated read-only; backup/restore test asserts the scenario snapshot can be restored |
| Excessive agency at the integration layer (the copilot autonomously triggers automation or mlplatform) | `automation.run` and `mlplatform.deploy` require approval at the integration boundary; `copilot.run` budget envelope caps total integration cost; no-go conditions halt the platform if any interface exceeds its SLO |
| Overreliance on upstream subsystem outputs (a flawed ER or triage score propagates as fact) | `triage.score` returns a `calibrated_prob` and an `abstain` flag; `er.resolve` returns an `ambiguous_queue` for low-confidence matches; CP-FINAL `noGo=true` if any subsystem reports a faithfulness/SLO violation |
| Integration-layer prompt injection (a malicious payload traverses intake → ETL → RAG and reaches the copilot) | Schema validation at every interface boundary rejects malformed payloads before they propagate; synthetic scenario is CC0 and reviewed; no untrusted external data enters the pipeline; copilot web/SERP fences and verifier apply at the integration boundary too |

## 5. Operating modes

| Mode | Key required | Network | Use case |
|---|---|---|---|
| `LOCAL` (default) | no | no | Deterministic; CI-safe; all 12 stubs return canned responses |
| `DYNAMIC` | yes (for copilot) | only with a real adapter | Production wiring; missing key falls back to local copilot double |

## 6. Responsible-use notes

- No real PII is ever ingested; the shared scenario is generated by
  `data/generate.py` and is CC0.
- No automatic fraud or kinship inference is performed at any layer.
- The contribution statement and CV narrative explicitly disclaim outcomes
  beyond the synthetic scenario.
- Every subsystem's trace is aggregated; the CP-N4-C `redact()` applies to
  the merged trace.
- Backup/restore/rollback is demonstrated, not merely documented.

## 7. Limits

- The integration is exercised on a single synthetic scenario (ACME-001);
  it is not a production deployment.
- The contract tests use in-process stubs, not live servers.
- The copilot subsystem uses the deterministic local adapter by default.
- The platform does not handle real-time streaming; it is batch-oriented.

## 8. Versioning & reproducibility

- All twelve interfaces are versioned `/v1/` and additive-only.
- `contracts.py` pins the contract versions; breaking changes require a
  new `/v2/` and a migration ADR.
- `e2e_test.py` produces a deterministic trace (same input → same output).
- `backup_restore.py` proves a snapshot can be restored to a known state.
- `dependency_graph.json` records the upstream → CP-FINAL edge for each
  subsystem.
