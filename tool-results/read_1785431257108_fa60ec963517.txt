   633→   633→7. Required Audit Dimensions
   634→   634→Audit every capstone across these dimensions.
   635→   635→7.1 Structural presence
   636→   636→Verify:
   637→   637→* roadmap entry;
   638→   638→* ledger entry;
   639→   639→* gate section;
   640→   640→* section increment links;
   641→   641→* learner-facing capstone card;
   642→   642→* project brief;
   643→   643→* assessment;
   644→   644→* rubric;
   645→   645→* dataset;
   646→   646→* tests;
   647→   647→* badge dependency;
   648→   648→* final-capstone interface.
   649→   649→7.2 Curricular alignment
   650→   650→For every section in a level, map:
   651→   651→* theory contribution;
   652→   652→* I Do contribution;
   653→   653→* We Do contribution;
   654→   654→* You Do contribution;
   655→   655→* independent transfer task;
   656→   656→* assessment evidence;
   657→   657→* capstone artifact produced.
   658→   658→No section should claim to contribute to a capstone without producing a meaningful reusable artifact or competency.
   659→   659→7.3 Progression
   660→   660→Verify that scaffolding decreases:
   661→   661→Observe
   662→   662→→ complete guided parts
   663→   663→→ finish partially specified work
   664→   664→→ select methods independently
   665→   665→→ integrate under ambiguity
   666→   666→→ defend trade-offs
   667→   667→→ operate and recover a system
   668→   668→Do not make later projects larger only by adding more files.
   669→   669→Increase:
   670→   670→* autonomy;
   671→   671→* ambiguity;
   672→   672→* integration;
   673→   673→* stakeholder complexity;
   674→   674→* failure modes;
   675→   675→* operational responsibility;
   676→   676→* evidence burden;
   677→   677→* communication burden.
   678→   678→7.4 Authenticity
   679→   679→Verify that each project requires the learner to:
   680→   680→* make decisions;
   681→   681→* justify trade-offs;
   682→   682→* handle incomplete information;
   683→   683→* test normal, boundary and failure cases;
   684→   684→* communicate to a defined audience;
   685→   685→* confront ethical or security constraints;
   686→   686→* revise after feedback;
   687→   687→* produce inspectable evidence.
   688→   688→7.5 Technical completeness
   689→   689→Run:
   690→   690→* application;
   691→   691→* tests;
   692→   692→* demos;
   693→   693→* data generation;
   694→   694→* report generation;
   695→   695→* containers where applicable;
   696→   696→* service endpoints where applicable;
   697→   697→* browser flows where applicable;
   698→   698→* restore and rollback where applicable.
   699→   699→A Markdown description is not proof of implementation.
   700→   700→7.6 Assessment validity
   701→   701→Verify:
   702→   702→* outcomes and tasks align;
   703→   703→* the rubric measures intended capability;
   704→   704→* critical failures are non-compensatory;
   705→   705→* guided work is not counted as independent evidence;
   706→   706→* learners cannot pass using only provided solutions;
   707→   707→* localStorage cannot forge a verified award;
   708→   708→* the task can distinguish superficial completion from demonstrated capability.
   709→   709→7.7 Portfolio quality
   710→   710→Each capstone should produce a portfolio-ready package containing:
   711→   711→* concise problem statement;
   712→   712→* intended user;
   713→   713→* architecture;
   714→   714→* data;
   715→   715→* implementation;
   716→   716→* tests;
   717→   717→* metrics;
   718→   718→* limitations;
   719→   719→* responsible-use decisions;
   720→   720→* reproducible setup;
   721→   721→* demo;
   722→   722→* contribution statement.

   726→   726→* synthetic or legally reusable data;
   727→   727→* no secrets;
   728→   728→* no real PII;

   750→   750→8. Rubric Architecture
   751→   751→Preserve existing rubric versions until a migration is approved.
   752→   752→Research and implement level-sensitive rubrics.
   753→   753→Every capstone must include at least:
   754→   754→* functional correctness;
   755→   755→* data and failure handling;
   756→   756→* testing;
   757→   757→* architecture and maintainability;
   758→   758→* reproducibility;
   759→   759→* security and privacy;
   760→   760→* responsible use;
   761→   761→* evidence and observability;
   762→   762→* communication and demonstration.
   763→   763→Critical criteria must be non-compensatory.
   764→   764→Examples of automatic failure:
   765→   765→* real confidential data;
   766→   766→* committed secret;
   767→   767→* unsafe SQL;
   768→   768→* public sensitive attachment;
   769→   769→* automatic unsupported fraud or relationship inference;
   770→   770→* unapproved external side effect;
   771→   771→* fabricated test evidence;
   772→   772→* inaccessible core workflow;
   773→   773→* unresolved critical security defect;
   774→   774→* final demonstration that cannot be reproduced.
   775→   775→Default provisional gate:
   776→   776→Overall score ≥ 80%
   777→   777→All acceptance criteria passed
   778→   778→All critical criteria passed
   779→   779→No unresolved critical security, privacy or responsible-use failure
   780→   780→Calibrate through pilot evidence rather than assuming one rubric is psychometrically final.
